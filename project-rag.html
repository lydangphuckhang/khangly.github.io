Local RAG Chatbot

Un assistant conversationnel qui répond aux questions sur vos propres documents PDF et TXT, entièrement en local : aucune donnée ne quitte la machine. Les réponses s'appuient sur les passages retrouvés dans les documents, avec les sources affichées.

Contexte

Pourquoi un RAG local ?

Le problème

Les LLM grand public ne connaissent pas vos documents internes, peuvent inventer des réponses (hallucinations) et nécessitent souvent d'envoyer des données sensibles vers un service cloud.

La solution

Un pipeline RAG (Retrieval-Augmented Generation) qui indexe les documents dans une base vectorielle locale, retrouve les passages pertinents puis génère une réponse avec un petit LLM quantifié tournant sur un matériel modeste.

Mémoire conversationnelle

Comment le chatbot comprend les questions de suivi.

UtilisateurQu'est-ce que l'INSA Centre Val de Loire ?
AssistantRéponse générée à partir des passages retrouvés dans le document. Références : Source 1, Source 2
UtilisateurOù se trouve-t-il ?
Reformulation interne« Où se trouve l'INSA Centre Val de Loire ? »

Pourquoi c'est important

Une question comme « Où se trouve-t-il ? » ne contient aucun mot-clé utile pour la recherche vectorielle. Le chatbot utilise d'abord le LLM pour résoudre le pronom grâce à l'historique, puis lance la recherche avec la question reformulée. Résultat : des passages pertinents, même en pleine conversation.

Points forts

Les choix techniques qui font la différence.

Confidentialité totale

Modèle chargé depuis le cache local (local_files_only), aucun appel API externe.

Recherche MMR

Maximal Marginal Relevance (λ = 0,5) : équilibre entre pertinence et diversité pour éviter les passages redondants.

Optimisé pour petit GPU

Quantification 4 bits (BitsAndBytes), répartition automatique GPU/CPU : 1,8 Go de VRAM maximum, le reste déchargé sur CPU.

Embeddings sur CPU

Le modèle d'embedding tourne sur CPU pour réserver la mémoire GPU au LLM.

Sources affichées

Chaque réponse liste les passages utilisés, consultables directement dans l'interface Chainlit.

Anti-hallucination

Prompt strict : si la réponse n'est pas dans le contexte, le modèle doit dire qu'il ne sait pas. Température basse (0,1).

# Conversational RAG chain built with LCEL
retriever = get_retriever(vector_store, k=2)   # MMR

rag_chain = (
    RunnablePassthrough.assign(
        standalone_question=question_generator   # 1. rewrite question
    )
    .assign(
        source_documents=lambda x: retriever.invoke(
            x["standalone_question"]           # 2. MMR retrieval
        )
    )
    .assign(
        answer=answer_chain                     # 3. generate answer
    )
)

Limites actuelles
  • La qualité des réponses dépend de la qualité des documents et du découpage.
  • Modèle de 1,5B paramètres : rapide et léger, mais moins puissant qu'un grand LLM.
  • L'ingestion traite actuellement un seul document à la fois.
Prochaines étapes
  • Ingestion par lots et incrémentale d'un dossier complet.
  • Métadonnées enrichies et citations précises (page, fichier).
  • Évaluation de la qualité de la recherche et comparaison d'autres embeddings.
  • Meilleure gestion des hallucinations.
